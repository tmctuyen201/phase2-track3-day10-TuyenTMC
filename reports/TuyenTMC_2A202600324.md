## 1. Architecture summary

The system implements a reliability gateway for LLM agent requests with three protection layers: a semantic cache (in-memory or Redis) for deduplication, per-provider circuit breakers to prevent cascading failures, and a fallback chain that routes through backup providers before returning a static error message.

```
User Request
    |
    v
[Gateway] ---> [Cache check] ---> HIT? return cached
    |                                 |
    v                                 v MISS
[Circuit Breaker: Primary] -------> Provider A
    |  (OPEN? skip)
    v
[Circuit Breaker: Backup] --------> Provider B
    |  (OPEN? skip)
    v
[Static fallback message]
```

**Key design decisions:**
- Cache checked first — avoids unnecessary provider calls
- Circuit breakers fail fast when OPEN — no retry storms
- Route reasons include provider name and path (e.g., `primary:primary`, `fallback:backup`, `cache_hit:0.92`)
- Full request timing measured at gateway level (includes routing overhead)
- Privacy keywords and date-sensitive queries bypass cache to prevent false hits

## 6. Redis shared cache

In-memory cache is per-process. In production with multiple gateway instances (e.g., Kubernetes pods), each instance has its own cache — causing redundant provider calls and inconsistent responses. `SharedRedisCache` solves this by storing entries in a central Redis instance accessible by all gateway processes, ensuring cache hits are consistent across instances.

### Evidence of shared state

```python
c1 = SharedRedisCache('redis://localhost:6379/0', 60, 0.5, prefix='rl:test:shared:')
c2 = SharedRedisCache('redis://localhost:6379/0', 60, 0.5, prefix='rl:test:shared:')
c1.set('shared query', 'shared response')
val, score = c2.get('shared query')
# Result: val='shared response', score=1.0
```

Two separate `SharedRedisCache` instances successfully read the same cached entry.

## 8. Failure analysis

**What could still go wrong:** Circuit breaker state is not shared across instances. In a multi-instance deployment, each gateway has its own circuit breaker state. If the primary provider fails, one instance may detect the failure and open its circuit, but other instances continue sending requests to the failing provider. This causes delayed detection, wasted requests during the detection window, and inconsistent routing behavior.

**What would you change:** Store circuit breaker counters in Redis using `INCR` and `EXPIRE` commands. When a failure occurs, increment a Redis counter. When the counter reaches `failure_threshold`, all instances see the circuit as OPEN. Implementation sketch:

```python
# In CircuitBreaker.record_failure():
key = f"rl:circuit:{self.name}:failures"
count = self._redis.incr(key)
self._redis.expire(key, self.reset_timeout_seconds)
if count >= self.failure_threshold:
    self._transition(CircuitState.OPEN, "shared_failure_threshold")
```

This provides shared failure detection, faster collective response, and consistent routing across instances.
